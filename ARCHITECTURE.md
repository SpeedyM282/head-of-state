## 1. Слои и направление зависимостей

```
ui  →  store  →  core
         ↑
        data  (внедряется параметрами, core не импортирует data напрямую)
```

- **core** — чистые детерминированные функции. Не импортирует НИЧЕГО из других слоёв (только свои файлы). Не знает про DOM, React, стор, сохранения.
- **data** — контент игры: реформы, события, профили стран, коэффициенты баланса. Только типизированные константы, ноль логики.
- **store** — Zustand-стор. Единственное место, где core и data встречаются: стор вызывает функции ядра, передавая им контент и состояние.
- **ui** — React-компоненты. Читают стор, вызывают его действия. Никогда не вызывают core напрямую и не считают игровую логику.

Нарушение направления зависимостей — самый дорогой класс ошибок в проекте: он делает невозможным серверный мультиплеер без переписывания.

## 2a. Стек карты выбора страны

`ui/components/WorldMap.tsx` рисует **одну** интерактивную карту через `react-simple-maps` (`ComposableMap` + `ZoomableGroup` + `Geographies`/`Geography`), а не вручную нарисованный SVG и не несколько карт-вкладок. Ключевая идея: проекция ФИКСИРОВАНА (`geoEqualEarth`, `rotate=[0,0,0]`, `scale`, посчитанный численно под всю сферу для текущего форм-фактора — см. §7a про 4 бакета кадров) и не меняется, пока не сменился форм-фактор (поворот/ресайз) — «зум в регион» это чисто `ZoomableGroup`'s пан/масштаб (controlled `center`+`zoom` props) поверх этой базы, а не подмена проекции. Это позволяет анимировать переход CSS-transition'ом (см. ниже), чего с меняющимся `rotate` добиться было бы нельзя.

- **Регионы** — `REGION_ISO_MAPS: Record<RegionKey, Record<string, string>>` внутри `WorldMap.tsx` (набор ISO-id на регион; `RegionKey` — 14-членный union, см. ниже) плюс `MAP_FRAMES: Record<MapFrameBucket, MapFrameConfig>` — предвычисленный `center: [lon,lat]` + `zoom` НА КАЖДЫЙ из 4 форм-факторных бакетов (не один общий набор — см. §7a, эта часть переехала туда при адаптивности v0.18), подобранные численно (не на глаз): строится bbox региона в пиксельных координатах ФИКСИРОВАННОЙ базовой проекции ЭТОГО бакета, `zoom` = во сколько раз его нужно увеличить, чтобы заполнить viewBox с равномерными полями, `center` = `projection.invert()` пиксельного центра этого bbox. Россия (для Восточной Европы) и Фиджи (для Океании) исключены только из расчёта bbox (пересекают антимеридиан и разнесли бы кадр) — как страны они остаются в регионе и кликабельны после входа в него.
- **Слитые силуэты регионов** — `REGION_MERGED_GEOMETRY: Record<RegionKey, GeoMultiPolygon>` вычисляется один раз при загрузке модуля: для каждого региона геометрии его стран из `worldTopology.objects.countries.geometries` (только `Polygon`/`MultiPolygon`, остальные типы отфильтрованы) передаются в `topojson-client`'s `merge(topology, geometries)`, который растворяет общие рёбра между соседними странами одной топологии в одну фигуру без внутренних границ — ровно то, что нужно для общего вида карты (не имитация заливкой, а честное геометрическое объединение). Это единственная причина, по которой `topojson-client` стал прямой (а не только транзитивной через `react-simple-maps`) зависимостью проекта.
- **Состояние и два слоя геометрии** — `activeRegion: RegionKey | null` живёт в `MapScreen` (не в `WorldMap`), передаётся вниз вместе с `onEnterRegion`/`selectedCountryId`/`onSelectCountry`. На карте одновременно два слоя: (1) обычный `<Geographies>` рендерит все ~180 стран мира — страны, входящие в регион, который сейчас не активен (включая случай `activeRegion === null`, когда ни один регион не активен), рендерятся полностью невидимыми и некликабельными (`fill/stroke: none`, `pointerEvents: none`, стиль `STYLE_HIDDEN`), чтобы не задваивать их поверх силуэтов; страны активного региона получают настоящие границы и кликабельность (`onSelectCountry`); страны вне всех 14 регионов (территории без своего региона) — приглушённый инертный фон (`STYLE_CONTEXT`), но **только** при `activeRegion === null` (проп `showBackgroundContext`) — как только регион активен, они тоже переходят на `STYLE_HIDDEN`, так что на экране не остаётся ничего, кроме активного региона; (2) поверх — `RegionOverlay`, рендерящийся только при `activeRegion === null`, рисует 14 `REGION_MERGED_GEOMETRY`-силуэтов как отдельные кликабельные `<path>` (клик → `onEnterRegion(регион)`), используя `path` из `useMapContext()` (доступен только внутри `<ComposableMap>`). `MapGeography` получает явный булев `isRegionMember` от родителя, чтобы не путать «страна вне всех регионов» с «страна региона, который сейчас не активен» — раньше эти два случая было нечем различить (оба давали `alpha2 === null`).
- **Геометрия** — вендоренный `src/assets/world-110m.json` (TopoJSON стран мира, 110m, Natural Earth → пакет `world-atlas`, public domain/ISC; см. `src/assets/NOTICE.md`). Файл лежит в репозитории и не скачивается в рантайме — обязательное условие офлайн-работы под Capacitor. Он не используется напрямую: `dropMultiPolygonParts()` дважды пропускает его через себя при загрузке модуля — сперва отбрасывая часть геометрии Франции, которая на самом деле является французской Гвианой, затем части геометрии США, которые на самом деле Гавайи (в обоих случаях Natural Earth трактует эти удалённые территории как неотъемлемую часть страны, а не отдельную сущность на карте); результат (`worldTopology`) — то, что реально идёт и в `<Geographies>`, и в `REGION_MERGED_GEOMETRY`. Других подобных «прицепленных» территорий у стран в этой топологии на данном разрешении не обнаружено.
- **Сопоставление** — `data/countries/isoNumericWesternEurope.ts` / `isoNumericEasternEurope.ts` / `isoNumericNorthAmerica.ts` / `isoNumericSouthAmerica.ts` / `isoNumericCentralAsia.ts` / `isoNumericMiddleEast.ts` / `isoNumericSouthSoutheastAsia.ts` / `isoNumericEasternAsia.ts` / `isoNumericOceania.ts` / `isoNumericNorthAfrica.ts` / `isoNumericWesternAfrica.ts` / `isoNumericCentralAfrica.ts` / `isoNumericEasternAfrica.ts` / `isoNumericSouthernAfrica.ts` переводят числовой ISO 3166-1 (id геометрии в TopoJSON) в alpha-2 `CountryProfile.id`, по одному файлу на регион карты (Европа на карте — два региона на `europe.ts` с 40 профилями, Америка — два региона на `americas.ts` с 28 профилями, Азия — четыре региона на `asia.ts` с 44 профилями, Африка — пять регионов на `africa.ts` с 50 профилями; во всех случаях isoNumeric-файлы одного континента вместе покрывают его без пересечений). Страны без записи ни в одной из четырнадцати таблиц рендерятся как некликабельный фон (`pointerEvents: none`, приглушённая заливка) — они не «дыры» на карте, а просто визуальный контекст.
- **Анимация перехода** — `ZoomableGroup` рендерит `<g className="rsm-zoomable-group" transform="...">` (стабильный класс из самой библиотеки); `index.css` вешает на него `transition: transform 500ms ease`. Поскольку `transform` — SVG2-атрибут, современные браузеры анимируют его изменение через CSS transition как обычное свойство; в браузерах без поддержки переход происходит мгновенно (не ломается, просто не анимируется). `prefers-reduced-motion: reduce` уже глобально отключает все transition/animation в `index.css`, этот работает так же.
- **Производительность** — `<Geography>` обёрнут в собственный `React.memo`-компонент (`MapGeography`) со стабильными объектами стилей и `useCallback`-обработчиками, чтобы пан/зум (перевызывающий render-prop `<Geographies>` на каждый кадр) не перерисовывал все ~180 геометрий мира, а только те 1-2, у которых реально изменилось состояние выбора.
- **Ленивая загрузка** — `MapScreen` подключается в `App.tsx` через `React.lazy`/`Suspense`, а не статическим импортом: `react-simple-maps` + TopoJSON добавляют отдельный чанк, и без лени они утяжелили бы общий бандл существенно. С лени главный чанк остаётся на уровне до фичи, а карта подгружается только при переходе на экран карты.

## 3. Ключевые контракты

```ts
// Ядро — три главные функции:
initGame(content: GameContent, seed: number): GameState
applyPlayerActions(state: GameState, actions: PlayerAction[], content: GameContent): GameState
tick(state: GameState, content: GameContent, rng: Rng): TickResult
// TickResult = { state; triggeredEvent?; outcome? /* поражение/победа */ }
```

`content = buildContent(countryId, difficulty)` (`data/index.ts`) — страна и сложность выбираются до старта партии (карта Европы, см. GDD §10-11) и дальше едут вместе одним объектом; `initGame` внутри себя зовёт `deriveStartStats`/`deriveStartVector(content.country, content.difficulty)`, чтобы превратить профиль страны в стартовые показатели и вектор правления. Смена страны/сложности — это только смена входного параметра, ядро не знает о карте и не хранит списка стран.

- Всё состояние партии — один сериализуемый объект `GameState` (без классов, функций, Date). Это даром даёт сохранения, реплеи и передачу по сети.
- Случайность — только через `rng`, созданный из сида. `Math.random()` в core запрещён.
- Один ход = `applyPlayerActions` (реформы, ответ на событие) + `tick`.

## 4. Поток данных (реальное время)

Часы (`store/clock.ts`) — презентационный слой: они лишь решают, *когда* дёрнуть `tick()`. Ядро остаётся чистым и пошаговым (инвариант #1: ни `setInterval`, ни `Date.now()` в `core`).

1. `MainScreen` монтируется → `store.startClock()` (интервал живёт, пока экран смонтирован; на unmount — `stopClock()`).
2. `GameClock` копит прогресс месяца как долю [0,1); скорость (normal 20 c / fast 10 c на месяц) меняет только шаг, не прогресс — смена скорости в середине месяца не пропускает и не дублирует tick.
3. Каждый месяц clock зовёт `onTick` → стор вызывает `tick(state, content)` и сохраняет снапшот.
4. `tick`: пересчёт показателей → отложенные эффекты → grace-поражения (conditions) → в конце срока выборы (elections) → иначе выбор события (eventEngine).
5. Событие (`pendingEventId`) → clock авто-пауза; ответ игрока снимает её. Открытая панель реформ — тоже авто-пауза. **Ручная пауза имеет приоритет.** Победа на выборах (`awaitingInauguration`) → экран «Инаугурация» (фаза `interTerm`), затем `store.inaugurate()` продолжает игру. Исход (`outcome`) — `clock.stop()`.
6. UI между тиками: `buyReform` / `answerEvent` валидируются через core; `persistence` сохраняет снапшот после каждого действия и тика.

## 5. Правила для контента (data)

- Каждая реформа/событие описывается декларативно: эффекты — массив `{ target, delta }`, а не функции. Это позволяет балансировать без кода и хранить контент хоть в JSON.
- Исключение: сложные условия триггеров — предикаты `(state) => boolean`, но лежат рядом с данными события.
- Все «магические числа» формул (насколько экономика тянет одобрение и т.п.) живут в `data/balance.ts` с комментарием на каждый коэффициент. В core числовых констант нет.

## 6a. Локализация (i18n)

Поддерживаются три языка: **en (по умолчанию), ru, uz**. Ядро остаётся text-agnostic — это инвариант: core никогда не читает текстовые поля контента, поэтому определённость и логика симуляции от языка не зависят.

- **Контент** (реформы, события, имя страны) несёт текст inline как `LocalizedText = Record<Lang, string>` — сатира лежит рядом с механикой каждого элемента. UI выбирает язык через `loc(text, lang)`.
- **Фиксированные строки интерфейса** (кнопки, ярлыки статов/веток, заголовки зон, тексты поражений/побед) — перечислимые наборы, живут в `src/i18n/` (по словарю на язык), а не в data.
- `GameState` хранит только id (реформ, события) и не хранит текст → смена языка на лету пересобирает весь текст из контента, сейв остаётся валидным.
- Выбор языка хранится через `persistence` (`prezident.lang.v1`) — отдельный ключ localStorage, не смешанный с объектом сохранения партии (`prezident.save.v3`); `langStore` проставляет `<html lang>`.
- Менять язык можно только на экране «Настройки» (`ui/screens/SettingsScreen.tsx`, фаза `settings`, вход с главного меню) — единственная точка входа; применяется сразу, без кнопки подтверждения. Экран задуман расширяемым: будущие настройки — новые секции того же экрана, а не отдельные экраны.
- Тест `tests/i18n.test.ts` проверяет, что каждая `LocalizedText` и каждая UI-строка присутствуют и непусты во всех трёх языках, а структура ключей словарей совпадает.

## 6b. Обучение (tutorial)

Обучение — презентационный модуль поверх настоящей партии: `core`/`data/balance.ts` не участвуют вообще, `initGame` вызывается ровно так же, как в любой другой партии за Абсурдистан. Ответственность разделена на три слоя, каждый в своём месте на оси `ui → store → core`:

- **`ui/tutorial/content.ts`** — декларативные данные, ближе к `data/`, чем к логике: `SCRIPTED_STEPS` (7 шагов с `id`, `LocalizedText`-текстом Советника, опциональным `anchor: TutorialAnchor`, опциональным `advanceOn` — какие шаги не пропускаются кнопкой «Дальше», а ждут реального действия игрока) и `JIT_TIPS` (одноразовые подсказки, каждая — `id` + `LocalizedText` + чистый предикат `(state, content, ctx) => boolean`, где `ctx` несёт только `initialZone` — зону вектора на начало игровой сессии). Живёт в `ui/`, а не в `data/`, потому что описывает поведение интерфейса (что подсвечивать, когда показывать), а не игровой контент; **никогда не импортируется из `store/`** — только из `TutorialOverlay.tsx` — чтобы стор не знал о конкретных текстах и id шагов сценария, только об их абстрактной последовательности.
- **`store/tutorialStore.ts`** — Zustand-стор, зеркалящий свой собственный урезанный union шагов (`ScriptedStepId`) и состояние JIT (`jitEnabled`, `seenTips`, `activeTipId`, `initialZone`). Действия: `beginScripted`/`advanceScripted`/`skip` (сценарий), `notifyReformsOpened`/`notifyReformPurchased` (шаги 5-6, которые не продвигаются «Дальше» — стор только проверяет, что сейчас нужный шаг, и переходит дальше; сам факт «панель реформ открыта» / «реформа куплена» детектирует `TutorialOverlay.tsx` через `useEffect` над `gameStore`, не сам стор — стору думать об этом не нужно, ему только сообщают), `showTip`/`dismissActiveTip` (JIT, одноразовость — id пишется в `seenTips` и больше никогда не показывается), `resetForReplay` (сброс из «Настроек»), `captureInitialZone` (одноразовый снимок зоны вектора на старте сессии, живёт только в памяти стора — не персистится). Персистентные поля (`completed`, `seenTips`) читаются/пишутся через `persistence.ts`.
- **`store/persistence.ts`** — новый ключ `TUTORIAL_KEY = 'prezident.tutorial.v1'`, полностью отдельный от `prezident.save.v3` (игра) и `prezident.lang.v1` (язык) — тот же паттерн, что язык: настройка живёт вне сейва, «Играть снова» (`clearSave()`) её не трогает. Формат: `TutorialData = { completed: boolean; seenTips: string[] }`. `loadTutorial()`/`saveTutorial()` — try/catch-обёрнутые, как и остальная персистентность; малформед JSON и не-строковые элементы `seenTips` отфильтровываются, а не бросают исключение.
- **Якоря подсветки** — соглашение `data-tutorial="<id>"` на любом DOM-узле, который сценарий/подсказка может подсветить (`MainScreen`'s панель показателей/шкала вектора/часы/кнопка реформ, `ReformsPanel`'s вкладки веток и первый доступный узел дерева — последние два выставляются только пока активен шаг `reformsBuy`, не постоянно). `TutorialAnchor = string | string[] | null` — массив значит объединяющий bounding box нескольких элементов сразу (например, все вкладки веток разом). `useAnchorRect.ts` поллит `document.querySelectorAll` каждые 250 мс + на `resize` (а не завязывается на конкретный компонент через ref) — потому что подсвечиваемый элемент может перемонтироваться или менять позицию по причинам, не связанным с обучением.
- **Spotlight** — 4 прямоугольные затемняющие полосы (сверху/снизу/слева/справа от подсвеченной зоны) вместо одного элемента с `box-shadow`-вырезом: `box-shadow` не может заблокировать клики за пределами своего собственного прямоугольника, а сценарий обязан не пропускать клики мимо подсвеченного элемента, пока не наступил его шаг.
- **Auto-pause** — часы получили пятую причину паузы, `'tutorial'`, в том же `Set<string>` (`GameClock.setAutoPaused('tutorial', …)`), что `event`/`reforms`/`orientation`; ручная пауза по-прежнему приоритетна. Активна, пока не пройден шаг `release` — с этого шага и до конца партии часы больше не трогаются модулем обучения, JIT-подсказки лишь молча используют ту же причину `'tutorial'` для собственных одноразовых пауз.
- **Esc/назад** — перехватывается на capture-фазе (`addEventListener('keydown', handler, true)` + `stopPropagation()`) в `TutorialOverlay.tsx`, чтобы гарантированно сработать раньше остальных Esc-обработчиков экрана (закрытие панели реформ и т.п.) независимо от порядка монтирования компонентов.

## 7a. Форм-факторы и адаптивность

Три форм-фактора (см. GDD/задачу на адаптивность): **телефон-ландшафт** (`width < 1024px` И `height < ~500px` — единственная ориентация телефона, портрет полностью закрыт `OrientationGate` ниже), **планшет** (`width >= 768px` И `height >= 500px`, портрет и ландшафт оба разрешены) и **десктоп** (`width >= 1280px`, `pointer: fine`). Приложение было построено «портретной колонкой» — этот заход переразметил его под три формата, не тронув `core`/`data`.

- **Мобильно-первый CSS, без префиксного JS.** Безпрефиксные Tailwind-классы теперь означают телефон-ландшафт (раньше означали портретную колонку — она больше не существует как достижимое состояние на телефоне). `src/index.css` объявляет два `@custom-variant` (Tailwind v4, замена `tailwind.config`'s `theme.screens` для нестандартных условий): `tablet` — `@media (min-width: 768px) and (min-height: 500px)`, `desktop` — `@media (min-width: 1280px) and (pointer: fine)`. Оба — обычные `min-width`-условия без взаимного исключения (пересекаются на широких экранах); `desktop` объявлен ПОСЛЕ `tablet`, поэтому на пересечении в каскаде побеждает он — та же модель, что у родных `sm`/`md`/`lg` Tailwind (позже объявленный брейкпоинт побеждает при пересечении). Широкий (`>=1280px`), но не `pointer: fine` планшет (сенсорный) получает только `tablet:`.
- **Единственный JS-хук** — `ui/hooks/useViewport.ts` (`width`/`height`/`pointerFine` из `window.innerWidth/innerHeight`/`matchMedia('(pointer: fine)')`, обновляется по `resize`/`orientationchange`). Используется ровно в двух местах, где CSS принципиально не выразим:
  1. `OrientationGate` (см. ниже) — потому что его триггер должен ещё и дёрнуть сторовый экшн, а не только сменить класс.
  2. `WorldMap` — потому что его входные параметры (`ComposableMap`'s `width`/`height`/`projectionConfig.scale`, `ZoomableGroup`'s `center`/`zoom`) — числа для d3-проекции, не CSS. `classifyFormFactor()` из этого хука зеркалит ровно те же брейкпоинты, что и `tablet:`/`desktop:` custom variants, так что выбор бакета кадра всегда совпадает с активной раскладкой.
  Больше нигде в приложении JS не решает раскладку — переключение per-компонент идёт через `tablet:`/`desktop:` Tailwind-классы.
- **`OrientationGate`** (`ui/components/OrientationGate.tsx`, смонтирован в `App.tsx` вне переключателя `phase`, поверх всего) — веб-фолбэк блокировки ориентации (Capacitor ещё не подключён, см. TODO в §7). Триггер — `width < 768 && height > width` (телефон-размер и портрет). Пока активен: полноэкранный оверлей дизайн-токенов (пиктограмма поворота + локализованный текст, `ui.orientationGate`) поверх ВСЕГО (`z-50`), и эффект дёргает `store.setOrientationPaused(true)` — это та же причина авто-паузы часов, что `event`/`reforms` (`GameClock.setAutoPaused('orientation', …)`), поэтому ручная пауза по-прежнему имеет приоритет и правило не нарушается; тест — `tests/store/clock.test.ts`'s `describe('GameClock auto-pause')`.
- **Кадры карты (`WorldMap.tsx`)** — раньше один квадратный бакет 560×560 с зашитыми `center`/`zoom` на регион, подобранными численно под ЭТОТ квадрат; при не-квадратном контейнере (телефон-ландшафт 640×360, планшет-портрет 820×1180 и т.д.) это либо обрезало бы кадр, либо требовало реального пересчёта на лету. Решение — `MAP_FRAMES: Record<'phoneLandscape'|'tabletPortrait'|'tabletLandscape'|'desktop', MapFrameConfig>`: 4 бакета, каждый — свой `width`/`height` (viewBox), своя `worldScale` (fitSize сферы под этот box) и свой набор `center`/`zoom` на регион (тот же метод «bbox региона + 12%-марджин, инвертировать центр», что и раньше, просто прогнанный по разу на бакет). Числа получены одноразовым скриптом (не входит в поставку, не коммитится), который использует `d3-geo` НАПРЯМУЮ из `node_modules` (он уже резолвится транзитивно через `react-simple-maps`, но НЕ добавлен в `package.json` — банально одноразовый калькулятор, тот же принцип, каким наверняка были получены и предыдущие одиночные числа). `pickMapFrameBucket()` выбирает бакет по `classifyFormFactor()` + ориентации (портрет/ландшафт делит `tablet` пополам). Аспект бакета — представитель формата, а не точное совпадение с реальным вьюпортом (вьюпорты варьируются непрерывно) — `<ComposableMap>`'s штатный `preserveAspectRatio="xMidYMid meet"` леттербоксит расхождение, так что общий вид и любой регион остаются центрированными и **никогда не обрезаются и не искажаются**, независимо от точных пропорций реального экрана. `maxZoom` поднят до 11.5 (был 10) — самый плотный кадр среди всех бакетов (Ближний Восток на планшете-портрете) требует zoom 10.302.
- **Safe area.** `.safe-area-x` (index.css) добавляет `env(safe-area-inset-left/right)` к горизонтальным полям (только left/right — телефон всегда ландшафт, врезка грозит только с боков), с шагом базового отступа по тем же трём форматам. Применена на корневом контейнере `App.tsx` и на полноэкранных оверлеях, которые физически касаются краёв экрана (`ReformsPanel`, `OrientationGate`).
- **Тач-таргеты.** Все интерактивные элементы — `min-h-11` (44px) в безпрефиксной (телефон-ландшафт) раскладке; на десктопе части из них (кнопки-иконки, часы) сжимаются обратно через `desktop:h-8`/`desktop:h-9` — мышь не нуждается в 44px.
- **Плавные (fluid) токены типографики и отступов** (`src/index.css`, v0.22) — размер и «воздух» тоже растут от телефона-ландшафта к десктопу, но НЕ через брейкпоинты-модификаторы на каждый компонент (`sm:text-lg desktop:text-xl` и т.п.), а через `clamp()`-переменные, интерполирующие непрерывно между 640px и 1280px. 6 ролей шрифта — `--text-display` (заголовки экранов), `--text-heading` (заголовки панелей/событий), `--text-body` (текст событий/описаний), `--text-label` (названия статов/кнопки), `--text-caption` (eyebrow/строки эффектов/подсказки), `--text-num` (числа статов, `font-variant-numeric: tabular-nums` через класс `.num`) — растут неравномерно (display/heading ~1.4-1.6x, body/label ~1.15x, caption/num ~1.1x — крупный текст масштабируется заметнее мелкого, тот же принцип, что в type scale Utopia). 6 ролей отступов — `--spacing-sp-1`…`--spacing-sp-6` (~4/8/12/16/24/32px на телефоне → ~6/10/16/24/36/48px на десктопе), классы `p-sp-*`/`gap-sp-*`/`m-sp-*` и т.д. Объявлены напрямую под namespace'ами Tailwind v4's `@theme`, которые реально генерируют утилиты (`--text-*`, `--spacing-*`), не через слой-посредник с другими именами. Компонент размечается под роль ПО СМЫСЛУ элемента (не по тому, какой пиксельный размер там раньше стоял); единичные буквальные исключения, где токен ломает укладку на узком экране, задокументированы инлайн-комментарием рядом с местом (напр. `VectorScale`, вкладки веток в `ReformsPanel`). Тач-таргетов (см. выше) эти токены не касаются — `min-h-11`/`min-h-9`/`h-8` остаются буквальными Tailwind-классами.
- **Hover.** Tailwind v4's `hover:` уже сам компилируется в `@media (hover: hover) { &:hover {...} }` — не залипает на тач без доп. усилий. Кастомный класс `.btn` (не Tailwind-утилита) получил свой `@media (hover: hover)`-guard руками в index.css. `WorldMap`'s ховер стран/регионов — не CSS `:hover`, а `onMouseEnter`/`onMouseLeave`-пропы `react-simple-maps`'s `<Geography>` — на грубом указателе (`!pointerFine`) `STYLE_SELECTABLE_NO_HOVER` подменяет ховер-стиль на дефолтный, чтобы тап не оставлял фигуру «залипше» подсвеченной золотом.
- **Клавиатура.** `Space` — пауза/резюме (та же приоритетность «ручная пауза побеждает», что и у кнопок скорости), `Esc` — закрывает панель реформ (`MainScreen`) и досье/список стран (`MapScreen`). `EventModal` из Esc намеренно исключена — у события нет «отмены», ответ обязателен по дизайну (см. GDD §7).

## 7b. Дизайн-система: «Государственная ведомость» (newsprint ledger) и тёмная тема

v0.23 переразметила все 7 экранов под форму государственного бюллетеня/реестра — тонкие линейки, кикеры/колофоны капслоком, числа в реестровых строках с точечным лидером, герой-цифры как сбитые CMYK-плашки. Палитра, `.btn`-варианты и fluid-токены типографики/отступов уже существовали (v0.20-0.22, см. §7a) — это версия про раскладку и два новых сквозных механизма: тёмную тему и CMYK-цифры.

- **Один принцип раскладки на все форм-факторы.** До этой версии некоторые экраны (`ReformsPanel`) переключали структуру по брейкпоинту (верхние вкладки на планшете/десктопе vs левая иконочная колонка на телефоне). Теперь — везде одна структура; `tablet:`/`desktop:` только двигают `--text-*`/`--spacing-sp-*` через уже существующие fluid-токены, никогда не меняют flex-direction/видимость блоков. Это прямое следствие того, что макет дизайн-референса (`.dc.html`) сам по себе — один зафиксированный кадр 640×360, без брейкпоинт-специфичных версий; экстраполяция вверх — работа fluid-токенов, не альтернативных вёрсток.

- **Тёмная тема.** `store/themeStore.ts` (Zustand, зеркалит `langStore.ts`) хранит `Theme = 'light'|'dark'|'system'`, персистит в `prezident.theme.v1` (`persistence.ts`, тот же try/catch-паттерн, что `loadLang`/`saveTheme` и т.д.). `applyTheme()` пишет на `document.documentElement` **разрешённый** `data-theme` (`'light'` или `'dark'`, никогда буквально `'system'`) — так `index.css` нужен только один селектор `[data-theme="dark"]`, без дублирования логики `prefers-color-scheme` в CSS. При `theme === 'system'` модуль дополнительно подписывается на `matchMedia('(prefers-color-scheme: dark)')`'s `change`, чтобы живо следовать смене ОС-темы, а не только на старте.
  - **Единый блок переопределения.** `[data-theme="dark"]` в `index.css` меняет ровно 7 базовых hex-токенов — `--ink`/`--paper`/`--text-ink`/`--gold`/`--gold-deep`/`--stamp`/`--stamp-deep`. Все ДРУГИЕ токены (`--ink-soft`... нет, см. ниже; `--paper-dim`/`--paper-line`/`--text-faint`/`--gold-tint`/`--stamp-tint`/`--gold-soft`) — уже были объявлены через `color-mix(in srgb, var(--ink) N%, var(--paper))`-формулы в v0.20, поэтому пересчитываются бесплатно: `var()` внутри `color-mix()` резолвится в момент использования, не при объявлении.
  - **Единственное исключение — `--ink-soft`.** Его светлая формула (`color-mix(ink 82%, paper 18%)`) — «в основном ink» намеренно: это признак «утопленной» (recessive) поверхности — фон карты, трек прогресс-бара срока. При наивной замене базовых токенов формула стала бы «в основном НОВЫЙ ink», т.е. в основном СВЕТЛОЙ — противоположность тому, что нужно утопленной поверхности в тёмной теме. Поэтому `--ink-soft` переопределён явным литералом в `[data-theme="dark"]`, а не унаследован через формулу.
  - **`prefers-color-scheme`-фолбэк.** Отдельный `@media (prefers-color-scheme: dark) { :root:not([data-theme]) {...} }` с теми же 7 значениями — покрывает единственный момент, когда `data-theme` ещё не проставлен (самый первый рендер до того, как `themeStore.ts`'s модульный код выполнился); `themeStore.ts` immediately проставляет буквальный атрибут, так что в реальности этот блок работает доли миллисекунды, но исключает вспышку светлой темы на тёмной системе.
  - **`WorldMap`.** Заливки геометрии — токены (`STYLE_CONTEXT`/`STYLE_SELECTABLE` строятся на `var(--map-ocean)`/`var(--map-land)`), а не хардкод — суша/океан пересчитываются под тему сами по себе, без фильтров. `--map-ocean` — алиас `--ink-soft` (уже само явно переопределено под тёмную тему выше), `--map-land` — алиас `--paper-dim` в светлой теме, но явный литерал в тёмной: формула `--paper-dim` («N% ink к paper») в тёмной теме сходится к «в основном --paper», а он сам тёмный — суша слилась бы с океаном почти в один тон, если бы не явное переопределение (см. v0.25 в шапке файла за полной историей — там же была первая, неудачная попытка через `filter: invert(1) hue-rotate(180deg) ...` на `.map-canvas`, которая переворачивала карту НЕ в ту сторону, потому что светлая версия карты уже структурно «тёмный фон + светлая суша», в отличие от остального UI).
  - **`.cmyk-num`.** Строится на `--paper` как «бумажной подложке» плашки — на тёмной странице она бы уехала в грязно-тёмный. `[data-theme="dark"] .cmyk-num { --paper: #ece7db; }` переопределяет `--paper` ЛОКАЛЬНО (кастом-свойства каскадируют на потомков) только внутри `.cmyk-num`, так что подложка остаётся бумажной, а CMYK-плашки — процессными красками поверх неё.

- **`CmykNumeral`** (`ui/components/CmykNumeral.tsx`) — герой-цифра (очки влияния на `MainScreen`, месяцы у власти на `GameOverScreen`): 4 наложенных `<span>` — `.paper` (базовая/key-плашка на бумажной подложке) + `.plate-c`/`.plate-m`/`.plate-y` (`position:absolute`, `mix-blend-mode:multiply`, суб-пиксельные сдвиги через `transform: translate(...)`), имитируя сбитую цветоделённую печать. Цветные плашки — `aria-hidden`, для доступности читается только базовая. Оригинальный `.cmyk-num`/`.plate` CSS из референса не входит в бандл (внешний stylesheet `_ds/broadsheet-*/styles.css`, см. README хендоффа) — конструкция в `index.css` реализована заново по текстовому описанию механизма, не скопирована.

- **`SettingsScreen`: hub «меню → деталь».** Было — плоские две колонки (язык + справка/обучение) в одном экране. Стало — `type SettingsView = 'menu'|'language'|'theme'|'reference'`, **локальный** (не сторовый) `useState`, три `.set-row` (Язык/Тема/Справка, с текущим значением и шевроном) на менюшном виде, `.lang-row` (с чекмарком у выбранного) на язык/теме, две колонки (список тем справки + повтор обучения) на «Справке». Общий шеврон-назад — контекстный: из детали → в меню, из меню → `toMenu()`, тот же паттерн, что теперь и у `MapScreen`'s единственного шеврона (регион активен → выйти из региона; иначе → `toMenu()`).

- **`CountryDrawer.tsx` → `CountryDossier.tsx`.** Было — slide-in оверлей (`fixed inset-0`, полупрозрачный бэкдроп с `onClick={onClose}`, `translate-x`-анимация, свайп-жест сброса через pointer capture). Референс показывает досье как постоянную 184px-колонку **внутри** `MapScreen`'s собственного flex-row тела, рядом с картой, а не поверх неё — вся drawer-механика убрана, компонент — плоский `<aside>`, рендерится условно (`selectedCountryId &&`) как второй элемент flex-row. `difficulty`-состояние поднято в `MapScreen` (было локальным в дровере) и передаётся пропом, потому что теперь это не self-contained оверлей. `LevelBar.tsx` был единственным потребителем старого дровера — после переноса стал мёртвым кодом, хотя README хендоффа явно называл его целью правки; вместо удаления он переиспользован как общий `.led`-based компонент реестровой строки (тот же приём, что у `StatRow`), так что досье страны и внутриигровой реестр статов читаются одной идиомой.

- **Найденный визуальной проверкой баг.** «Список остаётся открытым после выбора страны» (v0.18: `MapScreen.selectFromList` не закрывает список, чтобы можно было сравнивать страны) плюс inline-досье (этот релиз) вместе ломали доступность кнопки «Выбрать»: `CountryListModal`'s непрозрачный полноэкранный бэкдроп (`z-20`) технически перекрывал клики по досье, которое рендерится сайблингом внутри `MapScreen`, а не внутри модалки. Тот же `pointer-events-none`-на-бэкдропе / `pointer-events-auto`-на-панели приём, которым уже был решён аналогичный случай для `CountryDrawer`, применён и здесь. Пойман прогоном Playwright по реальному флоу (headless Chromium, не входит в поставку) — статическая проверка типов/тестов такое не ловит, поэтому визуальная проверка стоит того при структурных изменениях оверлеев.
